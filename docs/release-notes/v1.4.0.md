# TLio 1.4.0

Release date: 2026-10-19 · [GitHub release](https://github.com/SQUORA-NL/TLio/releases/tag/v1.4.0)

> `add` appends to arrays the way JLio's `add` does, `copy` to the root replaces the document, and
> a set of path edge cases — wildcards before an index, bracket-quoted names, unions — now work.

## Highlights

### `add` appends to an array, as JLio's `add` does
A differential run of about 270 scripts against JLio 1.6.2 found `add` skipping an array it should
have appended to, and overwriting arrays it should not touch.

- `add` with a path that names an existing array appends the value:
  `{"command":"add","path":"$.filtered.tags","value":4}` turns `[1,2,3]` into `[1,2,3,4]`. It used to
  log "already exists, skipping".
- The same holds when the array is named through `property`
  (`path: "$.filtered", property: "tags"`), including every row of `$.rows[*]`.
- `add` through `$..name` appends to each array it matches instead of replacing the array with the
  value, and no longer overwrites a scalar it matches. `add` still never overwrites a scalar or an
  object.

Pinned by `Arrays/03`, `16` and `17` in `TLio.Parity.Tests` (JSON, XML and YAML) and by
`ArrayTargetParityTests`, which runs both JSON adapters.

### `copy` to the root replaces the document
`{"command":"copy","fromPath":"$.payload","toPath":"$"}` now makes the root exactly the copied
content, the same as JLio and as TLio's own `move`. It used to merge the source into the existing
root and keep the other properties.

## Fixed

- **Writing through a wildcard before an index crashed.** `add` or `put` on `$.rows[*].t[1]` threw
  `JsonException: Path returned multiple tokens`. Each matched array now gets the element when that
  is its next free position.
- **Bracket-quoted names.** `set` on `$['f']['tags']` did nothing and `add`/`put` created a property
  literally named `f']['tags`. A trailing bracket-quoted name is now the leaf, in both the Newtonsoft
  and the System.Text.Json adapters (the latter did not strip brackets at all).
- **Unions and the bare wildcard.** `set` on `$['f','items']` or `$.f.*` did nothing; both now write
  to every name or child they select. The bare `*` applies to `$`-rooted paths only — an XPath
  `/order/*` is still refused, on purpose.

## Upgrade notes

- **`add` on an existing array now appends.** A script that relied on `add` leaving an array alone
  when re-run will now append again each time, so it is no longer idempotent for arrays. Use `put`
  to set the array or `set` to replace it.
- **`copy` to `$` replaces instead of merging.** A script that copied into the root and counted on
  the existing properties surviving must merge explicitly with `merge`.
- `put` and `add` on `$.f.*` no longer create a property literally named `*`: `put` writes to every
  child, `add` skips children that already exist.
