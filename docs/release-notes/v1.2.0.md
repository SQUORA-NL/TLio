## Highlights

### Infix arithmetic in function values
Operators `+ - * / % ^` are parsed when the script is read and rewritten into the existing
`sum`, `subtract`, `multiply`, `divide`, `modulo` and `pow` calls from the Math pack, so nothing
new runs at execution time and the Math pack is still required.

```json
{ "command": "put", "path": "$.interest", "value": "=round($.principal * $.rate * $.yearFraction, 2)" }
```

Rules:

- **A binary operator needs whitespace on both sides.** Operator characters are legal in paths, so
  `$.a*$.b` and `$.unit-price` stay single paths.
- Operands are numbers, paths (`$`, `@`, and `/` for XML), quoted strings, calls and parentheses. A
  bare word is rejected with a reason.
- Precedence: `^` (right-associative) binds tightest, then unary `-`, then `* / %`, then `+ -`.
- Only text that is not a single plain call is considered, and that text used to resolve to an
  unknown function, so existing scripts keep their meaning. `==` is still the literal-`=` escape.
- A top-level parse failure writes nothing and logs the reason (`InvalidExpressionValue`); an
  invalid *argument* falls back to the old literal string with a warning.
- Wildcard paths flatten: `$.items[*].price * 2` is one number, not a list. This is recorded as
  decision A9 in [behaviour-decisions](../behaviour-decisions.md).

Full rules: [notation reference §3b](../ai-ref/notation-reference.md).
([#72](https://github.com/SQUORA-NL/TLio/pull/72))

## Upgrade notes

No breaking changes. A function value that contained a space-separated operator between operands
and previously produced an unknown-function result is now evaluated.
