# TLio 1.1.0

Released 2026-10-08 · [GitHub release](https://github.com/SQUORA-NL/TLio/releases/tag/v1.1.0)

> Loops, an own JSONPath engine, .NET 8/9/10 support, and a round of concurrency fixes that made
> parallel execution roughly six times faster.

## Highlights

### Loops: `forEach` and `while`
`TLio.Extensions.Looping` (opt in with `RegisterLooping`) adds the iteration primitive TLio lacked:
a script was a strictly linear list, and `decisionTable` and `resolve` loop internally without
exposing it. `forEach` runs a nested script once per element of an array; `while` repeats one while
a condition holds, with a required `maxIterations`. The current element is addressed with the
ordinary `@` / `@.field` token through a new `IExecutionContext.CurrentNode`, which is `null`
outside a loop. `set`, `add` and `put` resolve `@` paths against it, and a value such as
`@.field` reads the loop item while writing anywhere else in the document.

There is deliberately no `appendTo`; growing a list inside a loop is an ordinary idiom
(`concat` a delimited string, then `split` once after the loop), and in-place transformation is
`set path="@"`. In XML the current-item token is the XPath `.`. Also new: `dayCountFraction`
(`A360`, `A365`, `30E360`) in the TimeDate pack. ([#61](https://github.com/SQUORA-NL/TLio/pull/61))

### `TLio.JsonPath` — an own JSONPath engine
A standalone package for `System.Text.Json.Nodes.JsonNode`, with no dependency on TLio, Newtonsoft
or JsonCons. It replaces JsonCons in `TLio.Json.SystemText` and evaluates paths on the live node
tree instead of serialize → parse → select → navigate.

- Three dialects: `Newtonsoft` (default, held to Newtonsoft.Json 13.0.4 by differential tests),
  `Rfc9535` (the full standard including function extensions and I-Regexp) and `Extended`
  (Newtonsoft first, RFC 9535 for text Newtonsoft rejects).
- Verified: 706/706 on the pinned RFC 9535 compliance suite; differential tests against
  Newtonsoft over hand-written, repository-wide and generated corpora, plus an `[Explicit]` soak of
  about 1.8 million comparisons with no mismatch; every repository fixture and the command sweep
  produce identical output through both JSON adapters (`TLio.Json.AdapterParity.Tests`).
- Faster than the JsonCons strategy it replaces in every benchmark case, and faster than
  Newtonsoft's `SelectTokens` on lookups and large filters, slower on wide wildcards (1.9×) and a
  tiny filter (1.4×). Numbers and method: `docs/benchmarks/jsonpath-engine.md`.
- Rationale: `docs/adr/0001-tlio-owned-jsonpath-engine.md`.

([#68](https://github.com/SQUORA-NL/TLio/pull/68), [#69](https://github.com/SQUORA-NL/TLio/pull/69),
[#71](https://github.com/SQUORA-NL/TLio/pull/71))

### .NET 8, 9 and 10
Every library and test project builds for `net8.0`, `net9.0` and `net10.0` and is tested on each
runtime; applications stay `net10.0`. The list lives once in `Directory.Build.props`. .NET 8 and 9
reach end of support on 10 November 2026 and are dropped only in a major version after that. The
net10.0 build was also run on the .NET 11 RC1 runtime (compliance suite 706/706 and no mismatches),
and CI has an informational job that runs it on the newest preview runtime. Rules:
[target frameworks](../target-frameworks.md). ([#71](https://github.com/SQUORA-NL/TLio/pull/71))

### Concurrency: four shared-state bugs, found by a benchmark
A portfolio benchmark (a `while` + `forEach` + nested `ifElse` script over up to a million
documents) exposed four real problems:

1. `CommandBase.Clone()` was shallow, so the nested script of `while`, `forEach` and `ifElse` was
   shared across every "independent" clone of a compiled script, and concurrent executions raced on
   those commands' own state.
2. `FixedValue.GetValue()` returned its literal node by reference, so concurrent executions could
   splice the same node into two documents and Newtonsoft silently reparented it out of one.
3. The JSON path fetchers' array-index cache was a process-wide static, serializing every first-touch
   cache miss on one lock; it is per instance now.
4. `JsonNodeAdapter.TryGetDouble` used try/catch as its "is this numeric?" test, so almost every
   non-numeric comparison threw and caught a `FormatException`; the exception path takes a lock that
   does not scale across threads. It uses type checks and `TryParse` now, keeping the documented
   `"3,5" == 35` comma-as-thousands behaviour.

On a 14-core Apple M4 Pro: single-threaded throughput about 610 → 1,758 contracts/s, and parallel
about 1,780 → 10,400 contracts/s at one million contracts. **The rule that came out of it:** a
compiled script's commands are shared, concurrently executed singletons — request-scoped state
belongs on `IExecutionContext<TNode>`, never on a property of the command.
([#65](https://github.com/SQUORA-NL/TLio/pull/65))

### Quality gates
- Zero-warning build; nullable warnings are errors; CI builds with `-warnaserror`, runs on Linux,
  macOS and Windows plus an nl-NL locale run, collects coverage, and gates every `release/*` pull
  request on the `[Explicit]` concurrency checks. ([#67](https://github.com/SQUORA-NL/TLio/pull/67))
- A memory-growth test runs a shared compiled script in batches, forces a full GC after each and
  asserts the heap does not scale with execution count. The forced-concurrency tests are
  `[Explicit]` and run in the release gate. A BenchmarkDotNet project (`TLio.Benchmarks`) reports
  throughput, allocation, lock contention and effective cores used against a lock-free control
  workload. ([#66](https://github.com/SQUORA-NL/TLio/pull/66), [#62](https://github.com/SQUORA-NL/TLio/pull/62))

### Samples moved to their own repository
The sample applications, worked examples, command showcase and Azure demo now live in
[TLio-Samples](https://github.com/SQUORA-NL/TLio-Samples), which builds against the published
NuGet packages. This repository keeps the library, its packages and the reference documentation.
([#64](https://github.com/SQUORA-NL/TLio/pull/64))

Every package README now opens with a runnable quick start, and two examples in the docs were
corrected (`copy` takes `fromPath`/`toPath`; `tocsv` joins rows with the platform newline).
([#63](https://github.com/SQUORA-NL/TLio/pull/63))

## Breaking changes and upgrade notes

For `TLio.Json.SystemText` users:

- **Path dialect.** The default is now Newtonsoft's (it was JsonCons). `Rfc9535` and `Extended`
  are opt-in through `SystemTextJsonExecutionContext.CreateDefault(dialect)`.
- **Invalid paths throw `JsonPathException`** instead of silently selecting nothing.
- **`SelectNode` on a path with several matches throws**, like `SelectToken`, instead of returning
  the first.
- Numeric strings are parsed culture-invariantly (`"2.5"` used to become 25 under nl-NL).
- JsonCons is no longer a dependency.

Also:

- Anything that referenced the removed sample projects, `docs/samples`, `docs/showcase` or `demo/`
  must use TLio-Samples.
- Code that stored request-scoped state on a custom command should move it to the execution context
  (see the concurrency rule above).

## Known deviations

`Extended` counts negative indexes from the end (Newtonsoft crashes on them); in `match()`, `^` and
`$` anchor, as the compliance suite expects (`StrictIRegexp = true` restores the literal reading);
`\p{..}` does not classify supplementary-plane characters (a .NET limitation).
