# TLio 0.9.0

Released 2026-08-23 · [GitHub release](https://github.com/SQUORA-NL/TLio/releases/tag/v0.9.0)

> Write scripts in XML or YAML, change format in the middle of a script, 21 new functions, and
> version numbers that finally come from git tags.

## At a glance

| | 0.8.0 | 0.9.0 |
|---|---|---|
| Documented commands | 15 | 17 |
| Documented functions | 68 | 89 |
| NuGet packages | 12 | 13 (adds `TLio.FormatConverter`) |
| Target framework | net10.0 | net10.0 |

## Highlights

### Scripts can be written in XML and YAML
`XmlScriptParser` and `YamlScriptParser` already existed but nothing outside the tests ever used
them. They are now reachable: register them in one line and the notation is detected from the
text.

```csharp
var engine = new ScriptEngine<JToken>(commands, functions).UseXmlScripts().UseYamlScripts();
engine.Execute(scriptText, data, context);
```

Detection looks at the first meaningful character (`<` XML, `[`/`{` JSON, anything else YAML). A
JSON script stays JSON even though YAML would also parse it, so registering YAML cannot change an
existing script. Writing it surfaced a bug: structured values were rebuilt through the *data*
adapter from the *script's* text, so a YAML script on an XML document threw. Values now go through
JSON and `CommandConverter`. ([#38](https://github.com/SQUORA-NL/TLio/pull/38))

### `convert` works in the middle of a script
`convert` changes the format of the whole document partway through a script; commands before it
run against the old format, commands after it against the new one. `MultiFormatScriptRunner`
splits the script at each boundary and re-hosts every piece. Before this release a multi-format
script could report success having applied none of itself. The work also made the converter
trustworthy: the YAML writer now goes through YamlDotNet, `textProperty` and `namespacePrefix` do
what they say, and conversion output is the canonical document shape the commands after the
boundary can address. ([#41](https://github.com/SQUORA-NL/TLio/pull/41),
[#45](https://github.com/SQUORA-NL/TLio/pull/45))

### One package: `TLio.FormatConverter`
`convert` and `convertValue` were reachable from the MCP server and the samples but not from NuGet.
The five converter projects are now a single `TLio.FormatConverter` package, named and
namespaced like everything else. ([#46](https://github.com/SQUORA-NL/TLio/pull/46),
[#47](https://github.com/SQUORA-NL/TLio/pull/47), [#48](https://github.com/SQUORA-NL/TLio/pull/48))

### `title` and `description` on every command
Free text that nothing reads at run time, valid in all three notations, so a script stays readable
months later. In XML they are attributes only: a `<title>` child element is part of the value being
written. ([#42](https://github.com/SQUORA-NL/TLio/pull/42))

### 21 new functions
Chosen by reading real rating scripts and removing the idioms that cost four levels of nesting
([#43](https://github.com/SQUORA-NL/TLio/pull/43)):

| Pack | Functions |
|---|---|
| Math | `multiply`, `divide`, `clamp`, `sign` |
| TimeDate | `dateDiff`, `dateAdd`, `datePart`, `formatDate`, `parseDate`, `startOfMonth`, `endOfMonth` |
| Text | `regexReplace`, `regexExtract`, `right` |
| Built-in | `if`, `coalesce`, `between`, `distinct`, `sort`, `sortBy`, `last` |

For example, a driver's age was six calls four levels deep; it is now
`=dateDiff(birthDate,quotedOn,'years')`.

### Versions come from git tags
The tag is the version. MinVer stamps assemblies and packages from the nearest `v*` tag, so a local
`dotnet pack` produces what the pipeline produces and previews sort above the last release. A
**Release** workflow (patch / minor / major / exact) tags, publishes and cuts the GitHub release,
with guards that fail rather than publish a wrong number. `AssemblyVersion` stays major-only so
hot-loaded plugins keep binding. See [versioning](../versioning.md).
([#39](https://github.com/SQUORA-NL/TLio/pull/39))

### Faster repeated runs
Expressions inside an object or array `value` are parsed once when the script is read instead of on
every run (−24% on a 38-command script, −47% on a 60-expression template), and write commands only
build a trace when something collects one (about 8% per command). Trade-off: parsing is a little
slower, so break-even is about 1.2 documents. ([#50](https://github.com/SQUORA-NL/TLio/pull/50))

## Fixed
- **`resolve` did not write values in XML** — the `value` of a resolve setting (`@.field`) now reads
  the matched entry. The cross-format sweep could not catch it because it wrote a key the
  converter ignores.
- **`put` of an object onto a predicate path emptied the collection** — writing one entity removed
  the other three (JSON filters too).
- **`convert` was unreachable from XML and YAML scripts**; the MCP server also refused non-JSON
  convert scripts and the CLI built section engines without the XML/YAML parsers. Both fixed, and a
  section executor now fails with the remedy instead of passing the document through.
  ([#45](https://github.com/SQUORA-NL/TLio/pull/45))
- **A serialized script lost its configuration** — `TLioConvert.Serialize` knew six property shapes
  and dropped the rest, so a `decisionTable` came back without its config and a `resolve` without
  settings. It is reflective now. ([#49](https://github.com/SQUORA-NL/TLio/pull/49))
- Converter data loss and crashes found while making `convert` work: YAML → XML threw on arrays,
  XML attributes and element names vanished in JSON/YAML, arrays of one became objects, types and
  nulls were lost, namespaces threw, and keys were rewritten silently.

## Breaking changes and upgrade notes

- **Assemblies are strong-named.** Every assembly is signed with `tlio.snk`; assembly identity
  changed, so anything compiled against an unsigned TLio must be recompiled. The signature is an
  identity mechanism, not a security one: NuPlane's shared-assembly policy keys on the public key
  token.
- **Plugin host**: the Docker plugin host moved to NuPlane and CShells, and all dependencies moved
  to their latest stable versions (YamlDotNet 16 → 18 among them). Check your own pins.
- Package versions: previews published before this release (`0.1.0-preview.N`) sorted below
  0.8.0, so `--prerelease` consumers were pinned to something older than the release. Previews
  now always sort above the last release tag.
