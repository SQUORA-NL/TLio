## What TLio is at this release

TLio is a format-neutral scripting framework: a script is an ordered list of commands
(`add`, `set`, `put`, `remove`, `merge`, …) whose values may be `=function()` expressions, and it runs
unchanged against any document the configured adapter understands. The path language (JSONPath,
XPath, dot notation) is injected, not assumed.

- **Core** (`TLio.Core`, `TLio.Commands`, `TLio.Functions`, `TLio.Client`): `ScriptEngine`,
  parse-once `CompiledScript<TNode>`, a fluent `TLioScript` API, `TLioConvert`.
- **Format adapters**: `TLio.Json` (Newtonsoft), `TLio.Json.SystemText`, `TLio.Xml`, `TLio.Yaml`.
- **Extension packs**: Math, Text, TimeDate and ETL (`flatten`, `restore`, `resolve`, `tocsv`).
- **Format converter**: an intermediate model with JSON, XML and YAML adapters
  (`TLio.FormatConverter`, in the repository but not yet a package).
- **MCP server** (`TLio.Mcp`): lets an AI agent list, describe, execute and analyse TLio scripts.
- **Samples**: a CLI with batch mode, a minimal API with a slug-based compiled-script cache, and a
  Docker host that hot-loads extension packs with NuPlane.

## Highlights

### Null is an unfilled container, in every format
One document written in JSON, XML and YAML now behaves the same under the same commands. The
class of failures behind *"add: cannot add property to a primitive node"* on empty or null nodes
is gone: `add` and `put` upgrade a null-valued node to an object (or to an array at position
`[0]`), and deep paths build through null intermediates. `set` stays strict. The cases where the
formats genuinely cannot agree are recorded in `docs/behaviour-decisions.md`, section E.

### XML paths follow XPath (breaking)
Paths now anchor on the document node, exactly as XPath defines it: `/order` is the document
element and must be named. A bare `customer` or `/customer` no longer skips a level. See
[Upgrade notes](#upgrade-notes). ([#35](https://github.com/SQUORA-NL/TLio/pull/35))

### `rename` command
Changes a node's name while keeping its value, children, position and XML attributes.
In XML it renames the document element too. ([#35](https://github.com/SQUORA-NL/TLio/pull/35))

### Structural `compare`
`compare` now produces a list of differences (type, subtype, both paths, description) written as a
node array: deep object diff, positional or key-matched array diff, `resultTypes` filtering.
([#32](https://github.com/SQUORA-NL/TLio/pull/32))

### Key-based `merge`
`merge` matches array elements by key (`arraySettings[].keyPaths`), supports the `onlyStructure`
and `onlyValues` strategies, de-duplicates with `uniqueItemsWithoutKeys`, and guards with
`matchSettings`. ([#33](https://github.com/SQUORA-NL/TLio/pull/33))

### Predicates, and nested calls without `=`
Boolean functions for `ifElse` and `decisionTable` conditions: `and`, `or`, `not`, `equals`,
`notEquals`, `greaterThan`, `greaterOrEqual`, `lessThan`, `lessOrEqual`, `in`, `matches`,
`exists`, `isNull`, `isString`, `isNumber`, `isBoolean`, `isArray`, `isObject`. Inner function
calls no longer need their own `=`: `=concat(fetch($.a), ' ', fetch($.b))` evaluates. New
`toFixed`, and `format` now keeps numbers and booleans typed so `{0:F2}` works.
([#34](https://github.com/SQUORA-NL/TLio/pull/34))

### Also in this release
- Special-character escaping in values and paths; the unified script notation reference.
- Multi-document YAML parsed as an array root.
- `fetch` accepts quoted paths and computed paths from nested expressions.
- Every NuGet package ships its own README.
- An MCP server with discovery, execution and analysis tools.

## Fixed
- **All formats** — `add`/`put` into null nodes (see above).
- **System.Text.Json** — JSON `null` was invisible to path selection, so `remove`, `rename`,
  `copy`, `move`, `merge` and `=fetch` silently did nothing where Newtonsoft worked. Also:
  a `flatten` crash on null leaves, `Replace` moving a property to the end of its object, and
  `Parse("null")`. Any whole-number result of `sum`, `count`, `countif`, `length`, `indexOf`
  made the document impossible to serialize — now fixed. ([#37](https://github.com/SQUORA-NL/TLio/pull/37))
- **XML** — whitespace-only content no longer makes a node primitive; an element with no children
  is no longer a primitive (the reported `add /order/address/city` bug); a one-property object is
  no longer read as a one-element array; `AppendToArray` and `DeepMergeInto` keep array items
  apart. ([#36](https://github.com/SQUORA-NL/TLio/pull/36))
- **YAML** — a bare `key:` is null; sequences are no longer padded with empty mappings.
- **Script notation** — the XML parser dropped every non-string property (`condition`,
  `ifScript`/`elseScript`, settings objects, `destinationAsArray`); fixed. A cross-format
  differential harness went from 43/65 aligned cases to 65/65.
- **MCP server** — XML documents parse attached to their document, so absolute paths resolve.

## Upgrade notes

- **XML paths must name the document element.** Prefix existing XML paths with it:
  `customer` and `/customer` become `/order/customer`; `//customer` is unchanged.
  Any `XElement` handed to the engine must be a document element
  (`XmlNodeAdapter.Parse` returns one); a hand-built detached element silently falls back to the
  old relative resolution.
- Inner function calls without `=` are now evaluated. A literal that merely looks like
  `name(...)` with a registered name should be quoted.

## Validation

85-case cross-engine differential matrix (Newtonsoft, System.Text.Json, YAML, XML slash and
XPath); 70 new regression tests and 8 new parity fixtures; 2,369 tests green at release.
