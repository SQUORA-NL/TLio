# TLio 1.0.0

Released 2026-09-20 · [GitHub release](https://github.com/SQUORA-NL/TLio/releases/tag/v1.0.0)

> The first 1.x release. Small in code — `toArray`, `setProperties`, a documentation audit — on top
> of the command set, the three script notations and the converter introduced in 0.8 and 0.9.

## At a glance

| | 0.9.0 | 1.0.0 |
|---|---|---|
| Documented commands | 17 | 18 (adds `setProperties`) |
| Documented functions | 89 | 98 |
| NuGet packages | 13 | 13 |
| Target framework | net10.0 | net10.0 |

The function count rises by nine because eight Math-pack functions that had always existed were
documented for the first time (see below) and `toArray` was added.

## Highlights

### `setProperties` — write through a wildcard
`set`, `add` and `put` only recognise a multi-node target when the path ends in a bracket and a
subscript, so they cannot write through an object-key wildcard (`$.widgets.*`) or a multi-key union
(`$.obj['a','b']`). `setProperties` runs any value function against a selection of nodes under the
matched objects and replaces each in place. `properties` is either a literal list of names or
`@.`-relative paths, or a function.

`scriptpath` (and its alias `path`) gained a three-argument find mode,
`=scriptpath(*, kinds, recursive)`, that returns descendant nodes of the requested kinds
(`object`, `primitive`, `null`) as live nodes, ready for write-back — for example turning every
complex object in a tree into an array, deepest first.
([#55](https://github.com/SQUORA-NL/TLio/pull/55))

### `toArray`
The array sibling of `promote`. `=toArray(path)` wraps a node in a new array; with no argument it
wraps the current node, so applied over a wildcard it wraps each matched element individually.
A missing or null source gives `[]`; an array passes through as a clone and is never double-wrapped.
([#53](https://github.com/SQUORA-NL/TLio/pull/53))

### Documentation audit
All 17 commands and every core, Text and TimeDate function were documented; the Math pack was
missing eight: `subtract`, `calculate`, `sumifs`, `countifs`, `averageif`, `averageifs`, `minifs`,
`maxifs`. They have pages now, written from the implementation. The audit also corrected two false
claims — `sumif`/`countif` do support `>=`, `<=`, `<>`, `!=`, `>`, `<` and `*`/`?` wildcards.
([#56](https://github.com/SQUORA-NL/TLio/pull/56))

## Fixed
- The cross-format sweep comparison rendered numbers with the current culture, so on a machine whose
  region uses a decimal comma it compared `"2,5"` against recorded `"2.5"`. The comparison is
  culture-invariant. ([#54](https://github.com/SQUORA-NL/TLio/pull/54))

## Samples added

A moped (bromfiets) rating core modelled on a GIM calculation workbook — age and bonus-malus
rating, WA/casco/accident premium build-up and a 22-rule acceptance checklist — and an Azure
Functions demo page ("JSON becomes a programming language"). Both now live in
[TLio-Samples](https://github.com/SQUORA-NL/TLio-Samples).
([#51](https://github.com/SQUORA-NL/TLio/pull/51), [#52](https://github.com/SQUORA-NL/TLio/pull/52))

## Upgrade notes

Nothing in this release changes existing behaviour: `setProperties`, `toArray` and the three-argument
`scriptpath` are additions.
