# resolve

> Looks up one element of a collection by key and returns it, or one field of it —
> `=resolve($.party, 'refKey', 'p2', 'firstName')`.

> Not the ETL [`resolve` *command*](../commands/Resolve.md). The command writes derived values into
> **every** target row; this function fetches **one** value inside an expression. Ask
> `tlio_describe` for `resolve` with `type: "function"` to get this page.

## Syntax

```
=resolve(<collectionPath>, <keyField>, <keyValue>)
=resolve(<collectionPath>, <keyField>, <keyValue>, <returnField>)
```

## Arguments

| # | Type | Required | Description |
|---|------|----------|-------------|
| 1 | path | yes | The elements to search: an array (`$.party` — its members are searched) or a multi-match selection (`$.party[*]`). Resolved like any path argument, so `@`-relative paths work. |
| 2 | text | yes | `keyField` — the literal property name compared on each element. |
| 3 | value | yes | `keyValue` — a value, a path, or a nested call such as `fetch($.policy.partyRef[0])`. |
| 4 | path | no | `returnField` — a path **relative to the matched element**, in the document's own path language (`firstName`, `address[0].city` in JSON/YAML; `address/item[1]/city` in XML). Left out, the whole element is returned. |

## Returns

The first matching element (or its `returnField`), as it is in the document.

- **First match wins**, in document order.
- **Keys compare exactly as [`equals`](Equals.md) does** (`NodeComparison.AreEqual`): the number `7` matches the text `"7"`; two nulls match; text is compared case-sensitively.
- An element without `keyField`, and an element that is not an object, is **skipped** — not an error.
- **No match, or a `returnField` that matches nothing, fails** the function and logs a warning naming the arguments. Like `fetch` on a missing path, that fails the command it sits in, which leaves the document alone; wrap it in `=coalesce(resolve(...), 'default')` when "not found" is a normal case.

## Verified example

```json
{ "command": "put", "path": "$.holderName",
  "value": "=resolve($.party, 'refKey', =fetch($.policy.holder), 'firstName')" }
```

Input: `{ "party": [{"refKey":"p1","firstName":"Ada"}, {"refKey":"p2","firstName":"Grace"}], "policy": {"holder":"p2"} }`
Output: adds `"holderName": "Grace"`.

## Functions in the path

✅ `collectionPath` may be `@.party` inside [`forEach`](../commands/ForEach.md) / [`with`](../commands/With.md).
The key may be a nested call: the motivating case is a key found by another lookup —
`=resolve($.a.party[*], 'refKey', =fetch($.a.policy[0].party[?(@.entityType=='policyHolder')].partyRef[0]), 'firstName')`.

## When to use

- A mapping copies fields out of a *related* record found by a key (party by `refKey`, product by id) and the lookup would otherwise be a filter repeated in every value.
- A one-off lookup with a default: `=coalesce(resolve(...), 'n/a')`.

## When NOT to use

- Several fields from the **same** record: select it once with [`with`](../commands/With.md) and read `@.field`. `resolve` searches the collection on every call.
- Writing derived values into every row of a collection (a join): the ETL [`resolve` command](../commands/Resolve.md) indexes the reference collection once.
- Looking up by something other than equality on one field: put a predicate in the path and use `fetch`.

## Common mistakes

- **`returnField` in the wrong path language.** It is relative to the element and written in the document's language: `contact.mail` in JSON/YAML, `contact/mail` in XML. A plain chain of names is walked through the node adapter and means the same thing everywhere; a path with a subscript (`address[1].city`, `address/item[2]/city`) goes to the format's path engine, anchored on the element.
- **XML subscripts under the slash-path fetcher.** That fetcher addresses an element by its path without positions, so a subscripted `returnField` is reliable only for the first of several same-named siblings. Plain names and the native XPath fetcher are not affected for the lookup itself.
- **Expecting a cache.** There is none: a script edits the document between calls, so a cached collection would go stale. Cost is one pass over the collection per call — see [performance.md §3](../performance.md).
- **Passing a number as `keyField`.** It is a property name, not a position.
