# Implementation Plan: YAML Multi-Document as Array Root

**Branch**: `006-yaml-multidoc-array` | **Date**: 2026-04-06 | **Spec**: [spec.md](./spec.md)

## Summary

A YAML multi-document file (documents separated by `---`) is semantically
equivalent to a JSON array root. Currently `YamlNodeAdapter.Parse()` only
reads `yaml.Documents[0].RootNode`, silently discarding every document after
the first. The fix wraps N documents into a `YamlSequenceNode` when N > 1,
making multi-document YAML inputs addressable with the same path expressions
used on JSON arrays.

## Phase 0 — Research

No open unknowns. All technical decisions are determined by the existing
YamlDotNet API and TLio adapter contract.

### Decision: Use YamlStream.Documents for multi-doc detection

**Decision**: Branch on `yaml.Documents.Count` in `YamlNodeAdapter.Parse()`.

**Rationale**: `YamlDotNet`'s `YamlStream.Load()` already parses all
documents from a multi-document YAML string into the `Documents` list.
No custom parsing is required. Branching on the count (0, 1, or N > 1)
is the natural, zero-cost extension point.

**Alternatives considered**:

| Alternative | Rejected because |
|---|---|
| Add a separate `ParseMultiDoc()` method to `INodeAdapter<TNode>` | Breaks the single-entry-point contract; adds interface surface; callers would need to call the right method |
| Detect `---` markers manually before calling YamlDotNet | Reinvents what YamlDotNet already does correctly |
| Return the first document and silently discard the rest (status quo) | Data loss; breaks parity with JSON array roots |

### Decision: Output format for array root is YAML sequence (single document)

**Decision**: `Serialize(YamlSequenceNode)` produces a single YAML document
with a sequence at the root, not a multi-document file.

**Rationale**: `Serialize()` already wraps any `YamlNode` in a single
`YamlDocument`. This is consistent with JSON behavior (a JSON array
serializes as an array, not as N separate JSON values). No code change to
`Serialize()` is required.

**Alternatives considered**:

| Alternative | Rejected because |
|---|---|
| Serialize as multi-document output when root is a sequence | Requires a flag or new method; adds complexity; caller cannot always distinguish "array that was originally multi-doc" from "plain array root" |

## Phase 1 — Design & Contracts

### Data Model

No new entities. The existing `YamlNode` type hierarchy already covers the
case — `YamlSequenceNode` is the wrapper for multi-document results.

The behavioral contract change to `INodeAdapter<TNode>.Parse(string)`:

| Input | Previous output | New output |
|---|---|---|
| Single-document YAML | Root of the document | Root of the document *(unchanged)* |
| Multi-document YAML (N > 1 docs) | Root of first document | `YamlSequenceNode` containing N roots |
| Zero-document YAML | `IndexOutOfRangeException` | Empty `YamlSequenceNode` |

### Implementation change (single location)

**File**: `TLio.Yaml/YamlNodeAdapter.cs`, method `Parse(string content)`

```csharp
// Before (line 294–298):
public YamlNode Parse(string content)
{
    var yaml = new YamlStream();
    yaml.Load(new StringReader(content));
    return yaml.Documents[0].RootNode;
}

// After:
public YamlNode Parse(string content)
{
    var yaml = new YamlStream();
    yaml.Load(new StringReader(content));
    if (yaml.Documents.Count == 0)
        return new YamlSequenceNode();
    if (yaml.Documents.Count == 1)
        return yaml.Documents[0].RootNode;
    var sequence = new YamlSequenceNode();
    foreach (var doc in yaml.Documents)
        sequence.Add(doc.RootNode);
    return sequence;
}
```

No other files require changes.
