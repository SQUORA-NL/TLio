# Implementation Plan: Unified Script Notation

**Branch**: `010-unify-script-notation` | **Date**: 2026-04-20 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/010-unify-script-notation/spec.md`

## Summary

Formalise and document TLio's script notation rules in a single authoritative reference document, update all existing `ai-ref.md` files to be consistent, and add a parser warning for the `@propertyName` (no-dot) relative-path anti-pattern. The core parser behaviour is already correct; the work is primarily documentation and one minor validation addition.

## Implementation Phases

### Phase 1: Write the Notation Reference Document

1. Create `docs/ai-ref/notation-reference.md` following the structure in `data-model.md` and the contract in `contracts/notation-reference-api.md`.
2. Must cover all 9 sections (JSON-First Rule through XPath Special Cases).
3. Maximum 150 lines total (Article XI style rule).

### Phase 2: Add Parser Validation Warning

1. In `TLio.Client/FunctionConverter.cs`, after the `@` path-prefix branch, detect `@` followed by a non-`.` character (excluding `@@` escape and JSONPath filter context).
2. Emit `context.LogWarning(...)` with the message defined in the contract — do NOT throw; return `PathValue` as before (no breaking change).
3. Add the 4 fixture triplets and corresponding NUnit test cases.

### Phase 3: Audit and Update All ai-ref.md Files

For each file in `docs/ai-ref/functions/` and `docs/ai-ref/commands/`:
1. Replace abstract syntax placeholders (`a`, `b`, `str`, etc.) with `<argN>` form.
2. Add the standard notation note pointing to `notation-reference.md`.
3. Verify all examples use unquoted paths and single-quoted literals correctly.
4. Update `overview.md`: add notation reference link in Script Format section; fix the `010-bracket-write` issue reference to `fix/bracket-write`.

### Phase 4: Verification

1. Run `dotnet test` — all existing tests pass (no regressions).
2. Run Article I and IX compliance grep commands — zero results.
3. Update checklist at `checklists/requirements.md`.
