# Implementation Plan: Sample Projects — API and CLI

**Branch**: `005-samples-api-cli` | **Date**: 2026-03-28 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/005-samples-api-cli/spec.md`

## Summary

Add a `samples/` directory to the TLio solution containing two runnable reference projects:

1. **TLio.Sample.Api** — an ASP.NET Core Minimal API with one POST endpoint per supported data type (JSON, XML, YAML). Each endpoint accepts a raw payload, executes the bundled TLio script for that type, and returns the transformed result with the correct HTTP status code and `Content-Type` header.

2. **TLio.Sample.Cli** — a console application that accepts `--input <file>` and `--script <file>` arguments, auto-detects the format from the file extension, executes the transformation, and writes the result to stdout (or `--output <file>`). Exits 0 on success, non-zero on failure.

Both projects reference existing TLio library projects via project references and require no external services or NuGet packages beyond the solution.

## Technical Context

**Language/Version**: C# / .NET 10 (matches existing solution)
**Primary Dependencies**: ASP.NET Core Minimal API (built-in to .NET 10), TLio.Json, TLio.Xml, TLio.Yaml, TLio.Client
**Storage**: N/A — stateless transformations; scripts stored as embedded `.json` files
**Testing**: No test project for the samples (they ARE the demo); manual `dotnet run` verification
**Target Platform**: Cross-platform (Windows/Linux/macOS), development machine
**Project Type**: web-service (API sample) + CLI (console sample)
**Performance Goals**: API <500 ms per request; CLI <2 s for 100 KB input
**Constraints**: No authentication, no persistence, no external network calls, no configuration required beyond `dotnet run`
**Scale/Scope**: 2 projects, 3 data formats, 1 script per format per project
