# Implementation Plan: TLio MCP Server

**Branch**: `019-mcp-tlio-server` | **Date**: 2026-05-01 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/019-mcp-tlio-server/spec.md`

## Summary

Build a standalone MCP server (`TLio.Mcp`) that exposes five deterministic tools to AI agents: two discovery tools (list and describe commands/functions via `docs/ai-ref/` files), one execution tool (run a TLio script with per-command structured trace), and one gap-analysis tool (structural diff between input and target documents). Observability is mandatory and disableable via configuration. Rate limiting defaults to 20 req/min with retry-after responses. The only changes to existing TLio projects are additive: `ITraceCollector?` added to `IExecutionContext<TNode>` and null-guarded `Record()` calls appended to each command's `Execute()` body.

**Storage**: N/A — stateless, in-memory execution per request; configuration from `appsettings.json` / environment variables
**Testing**: NUnit; integration tests via MCP client in-process; fixture triplets for any engine execution-path tests
**Target Platform**: Windows / Linux console process; stdio transport
**Project Type**: Standalone tool / MCP server
**Performance Goals**: <= 1 s response for documents <= 1 MB; zero overhead from trace infrastructure when disabled
**Constraints**: Additive-only changes to TLio.Core / TLio.Commands; no new commands or functions; no format types in TLio.Core public API
**Scale/Scope**: Local developer / agent use; single-client stdio session; rate limit 20 req/min (configurable)

- **Config toggle**: `appsettings.json` + `TLIO_MCP_TRACE` / `TLIO_MCP_RATELIMIT` environment variable overrides

### Key design choices

**Trace attachment**: `McpTraceCollector` is instantiated per-request, assigned to the execution context before `ScriptEngine.Execute()`, and its collected `TraceEntry` list is serialised into `ExecuteResult.Trace`. When `Observability:Enabled = false`, `null` is assigned — no trace entries collected and no overhead.

**Discovery via ai-ref.md**: `AiRefReader` globs `docs/ai-ref/commands/` and `docs/ai-ref/functions/`. For `tlio_list_*` it extracts each file's first non-heading prose line as the intent summary. For `tlio_describe` it returns full file content as a markdown string. This guarantees Article XI compliance and zero documentation drift.

**Gap analysis algorithm** (in `StructuralDiffService`):
1. Flatten both documents to `Dictionary<string, string?>` (leaf path → scalar value).
2. Symmetric diff produces `Add`, `Remove`, `Mutate` items.
3. Rename heuristic: a `Remove` + `Add` pair where path-segment names differ by Levenshtein distance <= 1 and values are identical is collapsed to `Rename`.
4. Array reorder: same leaf values at different index paths → `Reorder`.
5. Refinement mode (`prior_trace` supplied): cross-reference change items against successfully-executed commands in the trace; mark matched items `Resolved`.

**Rate limiter**: `RateLimiterService` creates one `SlidingWindowRateLimiter` at startup. On every tool call, `TryAcquire()` is called first. If the lease is denied, `RetryAfter` metadata is read from the lease and returned in the structured error response (FR-014).

**Configuration**: `IOptions<McpConfiguration>` injected via standard `builder.Configuration.Bind()`. `Program.cs` additionally reads `TLIO_MCP_TRACE` and `TLIO_MCP_RATELIMIT` environment variables and maps them into the configuration layer, so no app code changes are needed to override defaults.
